# DriveGoLight! — โครงสร้างระบบการแสดงผลและการนำทาง (UI/UX Layout & Navigation System)

ฉบับ 1.0 · 14 ก.ย. 2569 · ใช้กับเว็บแอป (Next.js) และไฟล์ต้นแบบ · ค่าทุกตัวในเอกสารนี้ตรงกับที่ใช้ในโค้ด (`globals.css` ตัวแปร `--h-*`, `--z-*`, จุดตัด 768/1280)

## 1. หลักการออกแบบ 5 ข้อ

| # | หลักการ | ความหมายในระบบนี้ |
|---|---|---|
| 1 | **ที่เดียว หน้าที่เดียว** | ปุ่ม/เมนูแต่ละหน้าที่มีตำแหน่งเดียวทั้งระบบ (ปุ่มย้อนกลับ = ปุ่มอำพันล่างขวาเท่านั้น, สร้างเอกสาร = การ์ดอำพันในแถบไทล์เท่านั้น) — ไม่มีของซ้ำสองที่ |
| 2 | **แสดงทีละเรื่อง** | หน้าเมนูย่อยแสดง "ฟอร์มสร้าง" หรือ "ประวัติ" อย่างใดอย่างหนึ่ง ไม่ซ้อนกัน (กดไทล์ประวัติ → ประวัติ, กดการ์ดสร้าง → ฟอร์ม) |
| 3 | **ของลอยมีชั้นตายตัวและเปิดได้ทีละชิ้น** | ลิ้นชัก / แผงยืนยัน / ปฏิทิน / ป๊อปอัปลิขสิทธิ์ ใช้ลำดับชั้น z ที่กำหนด เปิดชิ้นใหม่ = ปิดชิ้นเก่า และของที่ซ่อนอยู่ต้องรับคลิกไม่ได้ |
| 4 | **CTA ต้องกดได้เสมอ** | ปุ่มบันทึก/ยืนยัน/ย้อนกลับ ต้องไม่ถูกแถบเมนู ลิ้นชัก หรือคีย์บอร์ดบัง — มี safe zone ที่คำนวณจากความสูงแถบจริง |
| 5 | **จอโตขึ้น = ใช้พื้นที่โตขึ้น** | ไม่มีกรอบกว้างคงที่ (ไม่ยึด A4) ยกเว้นหน้าพิมพ์เอกสาร; ตาราง/ฟอร์มยืดเต็มความกว้างเสมอ |

## 2. จุดตัดขนาดจอ (Breakpoints)

ใช้ **mobile-first / min-width เท่านั้น** (ฐาน = จอแคบสุด) มีจุดตัดเพียง 2 จุด → 3 โหมด

| โหมด | ช่วงความกว้าง (CSS px) | Media query | อุปกรณ์ที่ตั้งใจให้ตรง |
|---|---|---|---|
| **Mobile** | 0 – 767 | (ฐาน ไม่มี query) | มือถือทุกขนาด แนวตั้ง/แนวนอน |
| **Tablet** | 768 – 1279 | `@media screen and (min-width: 768px)` (เฉพาะความกว้างเนื้อหา) | iPad/แท็บเล็ต แนวตั้ง-แนวนอน, โน้ตบุ๊กจอเล็กที่ย่อหน้าต่าง |
| **Desktop** | ≥ 1280 | `@media (min-width: 1280px), print` | โน้ตบุ๊ก/จอตั้งโต๊ะ |

**แท็บเล็ตใช้หน้าตาเดียวกับมือถือ** (ปรับตามต้นแบบของทีม 16 ก.ย. 2569 — ดู §13.8)
ต่างกันแค่เนื้อหากว้างสุด 560px กึ่งกลางจอ และตัวหนังสือแถบล่างใหญ่ขึ้น
บล็อก `768px` เดิมทั้งหมดจึงย้ายไป `1280px` — เหลือไว้ที่ 768 เฉพาะกฎของหน้ากระดาษ (`.paper`)

**`, print` ในบล็อกเดสก์ท็อปไม่ใช่ของแถม** — หน้ากระดาษ A4 กว้างราว 794px ตอนพิมพ์
กฎชุดนั้นเคยมีผลตอนพิมพ์เพราะเขียนไว้ที่ 768px ถ้าย้ายเป็น 1280px เฉย ๆ งานพิมพ์จะกลายเป็นหน้าตามือถือ
(ทะเบียนสินค้าจะพิมพ์ออกมาเป็นการ์ดแทนตาราง) · กลับกัน กฎที่ต้องไม่มีผลตอนพิมพ์ต้องเขียน `screen and` เสมอ

กติกาเสริม
- **ห้ามใช้ max-width query** และห้ามเพิ่มจุดตัดอื่น (มีเทสต์ `css-layers.test.ts` บังคับ) — ทุกอย่างที่ต้อง "ต่างกันตามจอ" ให้เขียนเป็นกฎเพิ่มในสองบล็อกนี้
- การตัดสินใจโหมดใช้ **ความกว้าง viewport** ไม่ใช่ user-agent · หมุนจอแล้วโหมดเปลี่ยนได้ทันที (คอมโพเนนต์ที่ต้องรู้โหมดใน JS เช่น `SubnavPortal` ฟัง `matchMedia('(min-width: 768px)')`)
- ขนาดตัวอักษรฐาน 15px ทุกโหมด (ตาราง/ช่องกรอก 14px) · ปุ่มและไทล์สูงอย่างน้อย **44px** ทุกโหมด (ขนาดนิ้วโป้ง)

## 3. กายวิภาคของหน้า (Page Anatomy) และความสูงที่เป็นค่าคงที่

```
--h-topbar : 58px   แถบเมนูหลักบน (ทุกโหมด) / หัวหน้า (sticky ถัดจากเมนูหลัก)
--h-tabbar : 58px   แถบล่างบนมือถือ
```

| ชั้น (บน → ล่าง) | Mobile | Tablet | Desktop |
|---|---|---|---|
| A. แถบเมนูหลัก (`.rail`) | ไม่มี (ใช้แถบล่าง F + ลิ้นชัก) | เหมือน Mobile | เมนู 01–08 ไอคอน+เลข+ชื่อเต็ม + ผู้ใช้ + ออกจากระบบ · sticky |
| B. หัวหน้า (`.topbar`) | ชื่อหน้า 18px + คำอธิบาย 12.5px · **ปุ่มของหน้าไปอยู่ในลิ้นชัก** · sticky | เหมือน Mobile | ชื่อหน้า 19px + แถบเมนูย่อยบรรทัดเดียว + ปุ่มของหน้า · sticky ใต้ A |
| C. เมนูย่อย (`.subnav`) | ตาราง 2 คอลัมน์ใต้ B (ไม่ sticky) | เหมือน Mobile | ย้ายขึ้นไปอยู่ใน B (portal ที่ ≥1280) |
| D. แถบไทล์ของหน้า (`.tiles`) | ไทล์เต็มแถว 2 ใบ/แถว | แถวเดียว ห่อได้ | แถวเดียว |
| E. เนื้อหา (`.wrap`) | padding 11px · ล่างเผื่อ tabbar+22px | เหมือน Mobile แต่ **กว้างสุด 560px กึ่งกลางจอ** | padding 22–28px · **กว้างเต็มจอ ไม่จำกัด max-width** |
| F. แถบล่าง (`.tabbar`) | 6 ช่อง: หน้าแรก · ลูกค้า · รายรับ · สินค้า · รายจ่าย · เพิ่มเติม(☰) · **fixed bottom** | เหมือน Mobile (ตัวหนังสือ 12px) | ไม่มี |
| G. ปุ่มย้อนกลับลอย (`.backfab`) | fixed ขวาล่าง **เหนือ tabbar** (`bottom: 58+14px`) | เหมือน Mobile | fixed ขวาล่าง 18px |

ระยะ "ปลอดภัย" ของเนื้อหาด้านล่าง (Mobile): `padding-bottom = var(--h-tabbar) + 22px` เพื่อไม่ให้ปุ่มบันทึกในฟอร์มถูกแถบล่างบัง; แถบฟอร์ม (`.formbar`) ไม่ sticky บนมือถือ เพื่อไม่ชนกับคีย์บอร์ดที่โผล่มา

## 4. ลำดับชั้นของสิ่งที่ลอย (Stacking / z-index) — ป้องกันการบังกัน

| ตัวแปร | ค่า | ใช้กับ | กติกา |
|---|---|---|---|
| `--z-content` | 0 | เนื้อหาปกติ | — |
| `--z-sticky` | 10 | หัวตาราง แถบเครื่องมือที่ติดขอบ | ต้องต่ำกว่าเมนูเสมอ (เลื่อนแล้วไม่ทับเมนู) |
| `--z-nav` | 20 | แถบเมนูหลัก · แถบล่างมือถือ | |
| `--z-header` | 30 | หัวหน้าที่ sticky | อยู่เหนือหัวตารางที่เลื่อนผ่าน |
| `--z-overlay` | 40 | ฉากหลังทึบ (scrim) | ครอบทั้งจอ กดแล้วปิดของที่เปิดอยู่ |
| `--z-drawer` | 50 | ลิ้นชัก · แผงยืนยัน · ปฏิทิน · ป๊อปอัปลิขสิทธิ์ · แผงเมนูหล่น | มีได้ **ชิ้นเดียว** ในเวลาหนึ่ง |
| `--z-toast` | 60 | ข้อความแจ้งผล | `pointer-events: none` ไม่บังการกด |

กฎที่บังคับใช้ในโค้ด
1. **ของลอยทุกชิ้นเป็น `position: fixed` ยึดกับจอ** (ไม่ยึดกับกรอบหน้า) — แผงยืนยันจึงเห็นครบไม่ว่าจะเลื่อนหน้าไปไกลแค่ไหน
2. **ของลอยที่ปิดอยู่ต้อง `display:none` หรือ `pointer-events:none`** (ลิ้นชักที่เลื่อนซ่อน ฉากหลัง ปฏิทิน ข้อความแจ้ง) — ห้ามมีชิ้นโปร่งใสรับคลิกค้าง
3. **เปิดชิ้นใหม่ = ปิดชิ้นเก่าเสมอ**: เปลี่ยนหน้า (`render`/route change) ต้องเรียก closeDrawer + closeConfirm + closeCalendar; กด Esc ปิดชิ้นบนสุด; กดฉากหลังปิด
4. **Focus**: เปิดแผงยืนยัน/ป๊อปอัป → โฟกัสไปที่ปุ่มหลักในแผง; ปิดแล้วโฟกัสกลับปุ่มที่กดเปิด; ปุ่ม Tab วนอยู่ในแผง (focus trap) ตอนเปิด
5. **Hydration**: ของที่ย้ายตำแหน่งตามจอด้วย JS (เมนูย่อย) วาดที่เดิมบนเซิร์ฟเวอร์ก่อน แล้วค่อยย้ายเมื่อรู้ขนาดจอ — ไม่ให้ layout กระโดดผิดตำแหน่ง

## 5. รูปแบบการนำทาง (Navigation Pattern) แยกตามอุปกรณ์

### 5.1 Mobile (0–767) — ใช้มือเดียว (Thumb zone)

```
┌──────────────────────────┐  A  แถบบน 58px: ชื่อร้าน · ☰ (ขวาบน สำหรับเมนูรอง)
│  หัวหน้า (sticky)         │  B
│  [เมนูย่อย 2 คอลัมน์]     │  C  ไทล์สูง 52px  กดได้ทั้งใบ
│  เนื้อหา / ฟอร์ม          │  E  ตาราง → การ์ด (สินค้า) หรือเลื่อนแนวนอนในกรอบเท่านั้น
│                          │
│                    (←)   │  G  ย้อนกลับ ลอยเหนือแถบล่าง
├──────────────────────────┤
│ หน้าแรก ลูกค้า รายรับ สินค้า รายจ่าย ☰ │  F  แถบล่าง 58px  fixed  ทั้ง 6 อยู่ในระยะนิ้วโป้ง
└──────────────────────────┘
```

- **Bottom Navigation 6 ช่อง** = เมนูที่ใช้บ่อยที่สุดของหน้าเคาน์เตอร์ (หน้าแรก · ลูกค้า · รายรับ · สินค้า · รายจ่าย · เพิ่มเติม ตามลำดับต้นแบบ) — ช่อง "เพิ่มเติม" เปิด **ลิ้นชัก (Drawer)** ที่มีเมนูหลักครบ 01–08 + เมนูย่อยทั้งหมด + ออกจากระบบ
- **ปุ่มเครื่องมือของหน้า** (พิมพ์รายงาน · ส่งออก CSV · ปุ่มที่หน้าส่งมาทาง `actions` ของ Shell) ไม่อยู่ในหัวหน้า — อยู่บนสุดของลิ้นชักใต้หัวข้อ **"เครื่องมือของหน้านี้"** (ต้นแบบซ่อนทิ้งเลย เราไม่ตัดทิ้งเพราะปุ่มที่หายไปโดยไม่มีที่ไปคือฟีเจอร์ที่หายไป)
- **ลิ้นชัก** เลื่อนจากซ้าย กว้าง `min(88vw, 340px)` มีฉากหลังทึบ กดฉากหลัง/Esc/ปัดปิด · ตอนเปิด **เนื้อหาด้านหลังล็อกการเลื่อน** และแถบล่างยังอยู่ (ถูกฉากหลังคลุม กดไม่ได้)
- เมนูย่อยเป็น **ตาราง 2 คอลัมน์ใต้หัวหน้า** ไม่ใช่แถบเลื่อนแนวนอน (แถบเลื่อนบนมือถือมักมองไม่เห็นว่ามีต่อ)
- **Thumb zone**: ทุก CTA หลักของหน้าอยู่ล่าง (ปุ่มบันทึกในแถบฟอร์มท้ายหน้า, ปุ่มย้อนกลับลอยขวาล่าง) · ของที่ต้องกดบ่อยไม่วางมุมบนซ้าย
- **ไม่มีเมนูหล่น (dropdown) แบบเมาส์** — ใช้ลิ้นชัก/แผงเต็มความสูงแทน
- **รายการเอกสารเป็นการ์ดใบละบล็อก** (รายรับ · ขายหน้าร้าน · รายจ่าย · ใบวางบิล — ตั้งแต่ 16 ก.ย. 2569 ดู §13.9):
  ชิปชนิด + เลขที่ + ชิปสถานะ / ชื่อลูกค้า / ทะเบียนรถ / วันที่ + ยอดรวม + คงค้าง · **กดทั้งใบเปิดเอกสาร ไม่มีปุ่มบนการ์ด**
  · หัวข้อกลุ่มบอกจำนวนและมีปุ่ม "＋ สร้างใหม่" ของชนิดที่กรองอยู่
- **ตัวกรองช่วงเวลาเป็น dropdown เดียว** (`ช่วงเวลา ▾` หกพรีเซ็ต) — ไม่มีชิปหกปุ่มและไม่มีช่องกรอกวันที่เอง
- **ทะเบียนสินค้า**: ปุ่มสลับสองช่อง `🔎 ค้นหาสินค้า | ▤ เมนูและตัวกรอง` อยู่บนสุด (ค่าเริ่มต้นคือรายการ)
  · การ์ดต่อสินค้าแบบสามคอลัมน์ (รูป | ชื่อ+รหัส | ราคา+คงเหลือ) · ปุ่มแบ่งหน้าลอยมุมซ้ายล่าง (ดู §13.10)
- **ลูกค้า/ผู้ขาย**: รายชื่อเป็นการ์ดใบละคน (ชื่อ / ชิปชนิด · รหัส · โทร · ทะเบียนหรือเลขภาษี / `›`) + แถบค้นหากับปุ่ม `＋ เพิ่ม`
  · หน้ารายคนเปิดมาเป็น **การ์ดอ่าน** (ข้อมูล · จำนวนเอกสาร · ยอดคงค้าง · ประวัติเป็นการ์ดเอกสาร) กด `✎ แก้ไข` ถึงเห็นฟอร์ม (ดู §13.11)
- **หน้าแรก**: การ์ดเล็กตามต้นแบบทั้งหมด — ภาพรวมการเงิน 2×2 · ลูกหนี้/เจ้าหนี้รายคน · ค้างดำเนินการ · ภาษีสามใบ + หัก ณ ที่จ่าย
  ทุกใบพาไปที่เดียวกับปุ่มบนการ์ดใหญ่ของเดสก์ท็อป (ดู §13.12)
- **ลูกหนี้/เจ้าหนี้**: การ์ดรายคน (ยอดค้างรวม) → กดแล้วเห็นใบค้างของคนนั้นพร้อมปุ่มรับ/จ่ายชำระทุกใบ
- **ฟอร์ม**: ช่องกรอกคอลัมน์เดียวทุกช่อง · ตัวหนังสือในช่อง 16px (iPhone ไม่ซูมเอง) สูง ≥ 48px · ปุ่มท้ายฟอร์มเรียงลงเต็มแถว (ดู §13.13)
- **หน้ากระดาษพิมพ์**: บีบลงความกว้างจอตามต้นแบบ ป้ายและหัวกระดาษตัดบรรทัดได้ ไม่มีข้อความเลยขอบกล่อง — ตอนพิมพ์จริงผังเดิมทุกจุด
- ตารางประวัติบนมือถือ: เลื่อนแนวนอนได้ **เฉพาะภายในกรอบตาราง** (`.tablewrap`) หน้าไม่ขยายตาม

### 5.2 Tablet (768–1279) — เหมือนมือถือ เนื้อหากลางจอ

ปรับตามต้นแบบของทีม (16 ก.ย. 2569) — ต้นแบบสลับโหมดด้วยบรรทัดเดียว
`frame.className = 'frame ' + (d === 't' ? 'm mt' : d)` คือ **โหมดแท็บเล็ตคือโหมดมือถือ**

```
┌────────────────────────────────────────┐
│          หัวหน้า (sticky) เต็มความกว้าง          │ B
│        ┌────────── 560px ──────────┐        │
│        │ เมนูย่อย 2 คอลัมน์            │        │ C
│        │ เนื้อหา / ฟอร์ม              │        │ E
│        └───────────────────────────┘        │
├────────────────────────────────────────┤
│ หน้าแรก  ลูกค้า  รายรับ  สินค้า  รายจ่าย  ☰ │ F  แถบล่าง (ตัวหนังสือ 12px)
└────────────────────────────────────────┘
```

- **ทุกอย่างเหมือน §5.1** — แถบล่าง 6 ช่อง · ลิ้นชัก · เมนูย่อยตาราง 2 คอลัมน์ใต้หัวหน้า · ปุ่มของหน้าอยู่ในลิ้นชัก · ทะเบียนสินค้าเป็นการ์ด
- ต่างสองข้อ: **เนื้อหากว้างสุด 560px กึ่งกลางจอ** (`.main > .wrap`) และตัวหนังสือแถบล่าง 12px แทน 11px
- หัวหน้า/แถบล่างยังกว้างเต็มจอ — ขอบที่แคบลงคือเนื้อหา ไม่ใช่กรอบทั้งหน้า
- เหตุผล: อ่านบรรทัดยาวเต็มจอแท็บเล็ตแล้วสายตาต้องกวาดไกล และเลย์เอาต์ชุดเดียวแปลว่ามีที่ให้พังครึ่งเดียว

### 5.3 Desktop (≥1280) — Header Navigation เต็มรูปแบบ

- เมนูหลักเป็น **Top Nav เต็ม**: ไอคอน + เลข + ชื่อเมนู + ผู้ใช้/สถานะลิขสิทธิ์ + ออกจากระบบ (แถบเดียว 58px ไม่ต้องมี sidebar → เนื้อหากว้างเต็ม)
- เมนูย่อย/ไทล์/เนื้อหาเหมือน Tablet แต่โชว์คอลัมน์ครบ (`.opt` กลับมา) และตารางประวัติใช้คอลัมน์ความกว้างคงที่ (px) + คอลัมน์ชื่อ = ที่เหลือ จึง**ไม่มีเลื่อนซ้ายขวา**
- **ไม่จำกัดความกว้าง** (`.wrap` ไม่มี max-width) · หน้าพิมพ์เท่านั้นที่เป็น A4 (`.paper` 210×297 mm)
- คีย์บอร์ด: Enter = ช่องถัดไป (ทั้งระบบ), Esc = ปิดของลอย, Tab วนในแผง

## 8. โฟลว์หน้าเอกสาร (ใช้เหมือนกันทุกเมนู)

1. กดเมนูย่อย → **ฟอร์มสร้างใหม่ทันที** (เลขที่เอกสารถัดไปโชว์เลย, 5 บรรทัดว่างพร้อมยิงบาร์โค้ด)
2. แถบไทล์ด้านบน: `ประวัติทั้งหมด · ประวัติ<ชนิด> · [+ สร้าง (อำพัน)]` — กดประวัติ = **หน้าเปลี่ยนเป็นประวัติอย่างเดียว** (มีตัวกรองเวลา วันนี้/เดือนนี้/เดือนที่แล้ว/ปีนี้/ปีที่แล้ว/ปฏิทิน) กดการ์ดสร้าง = กลับเป็นฟอร์มอย่างเดียว
3. ปุ่มท้ายฟอร์ม: `บันทึก (เขียว) · ยกเลิก · 🖨 พิมพ์เอกสาร (อำพัน)` → แผงยืนยัน "ตรวจสอบถูกต้องแล้ว:" → บันทึกแล้ว **กลับหน้าเดิม** + แถบ "บันทึกเรียบร้อย [พิมพ์เอกสาร] [เปิดเอกสาร]" และฟอร์มใหม่พร้อมทำใบถัดไป (กดพิมพ์เอกสาร = บันทึกแล้วไปหน้าพิมพ์เลย)
4. Enter = ไปช่องถัดไปทุกช่อง · ในตารางรายการ: ช่องรหัสมีผลค้นหา → Enter เลือกตัวแรก, บรรทัดสุดท้ายว่าง → Enter เพิ่มบรรทัด

## 9. ตารางข้อมูล (Data tables) — กติกาความกว้าง

- ตารางประวัติ/ทะเบียน: `table-layout: fixed; width: 100%` · คอลัมน์ตัวเลข/สถานะ/ปุ่นกำหนดเป็น **px คงที่** · คอลัมน์ชื่อ (ลูกค้า/สินค้า) = ที่เหลือ และตัดบรรทัดได้ → รวมไม่เกินหน้าเสมอ
- ขนาดตัวอักษร: ข้อความ 14px · ตัวเลข mono 13px · **เลขที่เอกสารและชื่อลูกค้า 16px ตัวหนา** (สิ่งที่คนมองหาก่อน)
- Tablet ซ่อนคอลัมน์รอง (`.opt`) · Mobile ใช้การ์ด (สินค้า) หรือเลื่อนในกรอบ (ประวัติ)
- แถวรวมท้ายตาราง (`tfoot`) ตรึงคอลัมน์ตรงกับหัวตาราง
- แบ่งหน้า: ทะเบียนสินค้า 10/20 ต่อหน้า ตัวเลื่อน `‹ 1 2 [3] 4 … ›`

## 10. การเข้าถึงและคีย์บอร์ด

- ทุกไทล์/การ์ดเป็น `<a>` หรือ `<button>` จริง (ไม่ใช่ div) · `aria-current="true"` สำหรับตัวที่เลือก
- ลิ้นชัก/แผงยืนยัน/ป๊อปอัป: `role="dialog"` `aria-modal="true"` ปิดด้วย Esc · ฉากหลังเป็นปุ่มมี `aria-label="ปิด"`
- ปุ่มย้อนกลับลอย `aria-label="ย้อนกลับ"` · ปฏิทิน `role="dialog"` ปุ่มวันเป็น `<button>`
- คอนทราสต์ตัวหนังสือบนพื้นเขียวเข้ม/อำพัน ≥ 4.5:1 · เป้าหมายกด ≥ 44×44px
