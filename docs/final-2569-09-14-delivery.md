# ส่งมอบงาน implement (14 ก.ย. 2569)

ยึดกฎที่กำหนด: ต้นแบบ HTML เป็นข้อกำหนดพฤติกรรม ไม่ได้ copy markup · ใช้คอมโพเนนต์/ยูทิลิตี้เดิมก่อน (สร้างใหม่มีเหตุผลกำกับ) · inline style ในไฟล์ที่เพิ่มรอบนี้แทนด้วยคลาสของ design system (เหลือเฉพาะความกว้างคอลัมน์ `<col>` ซึ่งเป็นข้อมูลโครงตาราง และหน้าพิมพ์เดิมของโปรเจกต์) · DOM manipulation ในฟอร์มแปลงเป็น state (ฟอร์มสินค้า: รหัส/หมวด/บาร์โค้ด · ใบขาย: โฟกัสช่องยอด) — ที่ยังแตะ DOM มี 3 จุดที่จำเป็น: `subnav-portal` (createPortal ต้องมีเป้าหมาย DOM), `enter-to-next` (listener ระดับเอกสารครอบทุกฟอร์ม), `fit-to-page` (ต้องวัดความสูงกระดาษจริงตอนพิมพ์) · TypeScript strict ผ่าน ไม่มี `any`/`@ts-ignore` ในไฟล์ใหม่ · **โปรเจกต์ไม่มีระบบ i18n** ข้อความไทยตรงในโค้ดตาม pattern เดิมทั้งโปรเจกต์ · ไม่แตะ config/dependency (`package.json`, `tsconfig`, `next.config` ไม่เปลี่ยน) · **สคีมาเปลี่ยนตามที่ตกลงในแผน**: ไมเกรชัน 020–030 + `db/001_init.sql` — ถ้าต้องการให้แยก PR ส่วนสคีมาออกมาแจ้งได้

ตรวจก่อนส่ง: `tsc` ผ่าน · เทสต์ 331 ข้อผ่าน (DB-backed ข้ามในแซนด์บ็อกซ์) · ต้นแบบชุดทดสอบ 24 หมวด × 3 รอบ ผ่าน

## 3. เช็กลิสต์ทดสอบเอง (เรียงตาม flow ผู้ใช้)

**ก่อนเริ่ม** — ทำตาม `DEPLOY.md`: unzip ทับครบ → รันไมเกรชัน 020–030 → `rm -rf .next && npm run build` → เปิดแบบ Ctrl+F5 · ตรวจเมนูบนมี `09 พิมพ์ฟอร์มเปล่า` และเมนูสินค้ามี `05.7 สร้างชุดอะไหล่ซ่อมบำรุง` (ถ้าไม่มี = ยังไม่ได้ build ชุดใหม่)

1. **โครงหน้า** — เปิดทุกเมนูบนจอ 3 ขนาด: เมนูย่อยอยู่แถวเดียวกับชื่อหน้า ไม่ตัดบรรทัด · มือถือเป็น 2 คอลัมน์ · ปุ่มย้อนกลับมีปุ่มเดียว (ลอยขวาล่าง) · เลขเมนูย่อยเรียงไม่ข้าม
2. **ตั้งค่าร้าน 07.1** — ใส่โลโก้ ลายเซ็น ชื่อเจ้าของ บัญชีธนาคาร 2 บัญชี หมายเหตุมาตรฐาน → บันทึก → เปิดหน้าใหม่ค่าคงอยู่
3. **สินค้า 05.11 เพิ่ม** — บรรทัดแรก รหัส|บาร์โค้ด|หน่วย · ยิงบาร์โค้ดจริง → ขึ้น "ตรวจแล้ว EAN-13" · เลือกวิธีคิดต้นทุน · เลือกผู้ขาย 2 ราย · บันทึก → พิมพ์บาร์โค้ด · ทะเบียน 05.1 กด 05.8 ติ๊ก "วันหมดอายุ" → คอลัมน์ขึ้น · มือถือเห็นเป็นการ์ด
4. **ชุดอะไหล่ 05.7** — สร้างชุด: ชื่อ · ราคา A/B/C · เพิ่มวัสดุจากทะเบียน 2 รายการ + พิมพ์เอง 1 · กด Σ รวมต้นทุน → เห็นต้นทุน/กำไร · บันทึก → รายการชุดโชว์ A + B/C
5. **ลูกค้า 02.1** — เพิ่มผู้ติดต่อ: รหัสตั้งเอง (ลองซ้ำ → เตือน) · ที่อยู่ 9 ช่อง · รถ 2 คัน กรอกครบ 11 ช่อง (รวม อื่นๆ) · บันทึก → ตาราง 02.2 เห็นที่อยู่ "เลขที่ … หมู่ที่ … ซอย … ต./แขวง … อ./เขต … จ. …" ครบ · ปุ่มแถวไม่แตกบรรทัด
6. **ใบเสนอราคา 03.1** — เปิดเมนูย่อยเห็นฟอร์มทันที เลขที่ถัดไปขึ้น · พิมพ์ชื่อลูกค้า → ที่อยู่/ภาษี/โทร/รถ ขึ้นให้ · ลองพิมพ์ทะเบียนในการ์ดรถ → ลูกค้า+รถขึ้น · ยิงบาร์โค้ด 2 ครั้ง → จำนวน 2 · ค้น "ชุด" → เลือกชุดอะไหล่ → บรรทัด "ชุดอะไหล่ซ่อมบำรุง … (รายการ)" ราคา A · เปลี่ยนระดับราคาเป็น B → ราคาชุดและสินค้าเปลี่ยน · อาการที่แจ้ง/ตรวจพบ 3 บรรทัด · กดบันทึกโดยไม่ใส่ชื่อลูกค้า → ขึ้นข้อความตรวจสอบ · ใส่แล้วบันทึก → แผงยืนยัน → บันทึก → กลับหน้าเดิม มีแถบ "บันทึกเรียบร้อย [พิมพ์] [เปิด]"

## 4. สิ่งที่ยังค้าง / ต้องการข้อมูลจากทีม

1. **รันบน Postgres จริง** — เทสต์ DB-backed (migrations 020–030, fifo, billnotes, claims, backup-roundtrip) ยังไม่ได้รันในแซนด์บ็อกซ์ → ต้องรัน `npm test` บนเครื่องพัฒนา และ `npm run e2e`
2. **ยืนยันภาพหลัง build** จาก `/forms` และ `/stock/new` (ตามที่ตกลง) เพื่อปิดประเด็นไฟล์ไม่ทับ
3. **สคีมา** — ไมเกรชัน 020–030 แก้ตามแผน (ตาราง kits/kit_items, คอลัมน์ purged_at, vehicles.other, bank_accounts, ราคาชุด B/C ฯลฯ) ถ้าทีมต้องการรีวิว DDL แยก แจ้งได้
4. **ข้อมูลเก่า** — ชุดอะไหล่ที่สร้างก่อน 030 จะได้ B/C = A อัตโนมัติ · ใบเสร็จเก่าที่ไม่มี `kit_id` ไม่กระทบ
5. **e2e ใหม่** ยังไม่ได้เขียนสำหรับ: ถังขยะ, ชุดอะไหล่, ใบเคลม, ฟอร์มเปล่า, รับชำระตรงแถว (มีเฉพาะชุดทดสอบต้นแบบ) — ต้องการยืนยันว่าจะให้เพิ่มใน Playwright
6. **สิทธิ์** — ตอนนี้ถังขยะ/ชุดอะไหล่ผูกกับสิทธิ์ `settings.shop` และ `stock.product` ตามเมนูแม่ ถ้าต้องการสิทธิ์แยก (เช่น "ลบถาวร" เป็นสิทธิ์ของตัวเอง) ต้องเพิ่มใน `perms.ts`
7. **i18n** — โปรเจกต์ไม่มีระบบแปล ข้อความไทยอยู่ในโค้ดตามเดิม ถ้าจะเริ่มมีต้องตัดสินใจระดับโปรเจกต์
8. **inline style ที่คงไว้** — ความกว้างคอลัมน์ `<col style={{ width }}>` ในตารางพอดีหน้า/หน้าพิมพ์ และหน้าพิมพ์เดิมของโปรเจกต์ (pattern เดิม) — ถ้าต้องการย้ายเข้า CSS ทั้งหมดเป็นงาน refactor แยก
